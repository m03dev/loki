# EVOLVE - LOKI grows its own personal-agent core

LOKI builds its own "OpenHuman" inside itself, one step at a time, by itself (engine/evolve.py).
When LOKI is idle, the autopilot takes the first open line below (after the owner's own ideas
from Settings > Lab) and hands it to `improve_loki`: a background LOKI agent changes LOKI's code
in its own git worktree, runs every test suite, and ships only when all of them pass. That
agent ticks the line (`- [ ]` -> `- [x]`) in the same commit, so a finished step is finished on
every machine. A step that did not ship is tried again after 3 days, with what went wrong in
its prompt. Settings > Lab shows all of it; LOKI_EVOLVE (Settings > General) turns it on or off
(auto = only on the Windows PC, which is on 24/7).

Rules for every step: never remove a feature to make room; keep the window fast (no heavy
dependency without need); macOS and Windows; a test for what is built; the world keeps its
pixel cel-shaded look.

Since session 26 LOKI also carries code ported from OpenHuman (memory, sub-agents), OpenHands
(condenser, stuck detection, file editing, task tracker, command risk) and Scrapling (native web
reading) - see docs/THIRD_PARTY.md. LOKI is AGPL-3.0 since 2026-10-17 (public repository): take code only under licences compatible with it (MIT, BSD, Apache-2.0, GPL-3.0, AGPL-3.0, ...) - never proprietary or non-commercial code.

## Roadmap

- [ ] E13 No stray "L" in the window - the owner: "why is there an L at the center of loki? it doesnt make any sense". Remove the letter "L" placeholders: the big `.welcome-mark` in the middle of the home screen and the `.brand-mark` in the sidebar (app/ui/index.html lines with `>L<`, styles in app/ui/app.css and app/ui/glass.css). Replace them with LOKI's real mark (a small inline SVG of the fox, drawn in the pixel cel-shaded style, no external file) or nothing. Check app/ui/onboarding.js / gallery.js for other "L" placeholders too. Test: tests/test_ui_smoke.py stays green; add a check that no element in index.html is just the text "L".
- [ ] E15 Ground texture fix - the owner: "the ground texture ... clip mapping or something needs rework". The island ground in LOKI World flickers/clips: paths, pools, plaza, flower patches, blob shadows and decals fight the grass (z-fighting), and the ground texture swims/shimmers when the camera moves. Fix it in the Babylon renderer (app/ui/world_babylon.js - the static baked ground, blob shadows SHADOW_VS/FS, decals) AND the classic renderer (app/ui/world.js): give every ground layer its own small height step and/or zOffset (material.zOffset / depth bias) in a fixed order (grass < dirt/paths < plaza < shadows < decals), snap texture/dither to world space so it does not swim, and check near/far planes so depth precision is enough. Keep the pixel cel-shaded look (cel bands, ink lines, pixel grid, posterize). Test: a headless-Chromium screenshot test at 3 camera angles (tests/ with fake /world data) plus a pixel-stability check (two frames 1 px of camera move apart differ little on the ground).
- [ ] E14 Every machine's island is unique - the owner: "loki mac and loki pc islands look the same when they are not ... add rng elements ... completely depends on the machine using it". Right now only the roof colour differs. Make each machine's island a different place, generated from a stable seed of that machine (its name + OS from /world `self`, and for other machines their name): island outline/shape and size, terrain heights, palette/biome (e.g. Mac: birch + lavender meadow, PC: pines + autumn, others picked from 6+ biomes by seed), tree/rock/flower species and density, building styles and colours, the pond/waterfall placement, decorations and critters - deterministic per machine (same island every time on that machine), clearly different between the Mac and the PC. Your OWN island (home) uses your machine's seed; the other islands floating in the sky use theirs. Code: app/ui/world.js SCENERY / machineIsland / sceneList (seeded() exists), both renderers. Test: generate the islands for "mohameds-mac-mini"/Darwin and the PC's name/Windows and assert they differ in shape, biome and layout; screenshots of both.
- [ ] E12 A real loading screen, never a terminal - the owner: "instead of the terminal people should see a window with a loading screen of whats loading during start up or update whenever ... kinda like autodesk maya". Like Maya's splash: a small borderless window (pywebview, app/loki_app.py) that opens INSTANTLY at launch, before the engine: LOKI's mark and name, version, a progress bar and one line saying exactly what is loading now ("Checking for updates", "Testing the new version (pre-flight)", "Installing new packages", "Starting the engine", "Loading models", "Starting MCP servers", "Loading memory", "Opening the window"), then it closes when the main window is ready. The engine and updater report their steps to it (a small status file or the engine's /health startup phases). It also shows during "Update everything", an automatic update, a restart and a rollback ("Going back to the last version that worked: <why>"). No console/terminal window ever on Windows (Loki.cmd / the shortcut must launch with pythonw or a hidden console; Loki Studio.cmd too) or macOS. Errors show in the splash with the log tail, never a blank window. Test: tests/ with the splash in headless Chromium + a fake engine walking through the phases; app/loki_app.py --self-test stays green.
